# AGENTS.md — @trdlabs/sdk

Часть экосистемы `trdlabs`. Кросс-репозиторные вопросы — архитектура, контракты, раскатка,
локальный стек — из [`../control-center/AGENTS.md`](../control-center/AGENTS.md): там канонический
порядок чтения и карта владения. Соседа рядом нет (отдельный клон) — работать по локальным документам.

## Что это

Публичный contract-first SDK — каноническая типизированная обёртка над consumer-поверхностью
платформы. Отдельный репозиторий, без runtime- и build-связности с приватной `platform`.

**Любое изменение здесь — изменение контракта.** Оно достаёт `lab`, `office`, `backtester`,
`mock-platform` и внешних потребителей npm. Что входит в поверхность — `exports` в
`package.json` и снимок `api-surface.txt`; сюда список не дублируется.

Не входит: рантайм платформы, живое исполнение, биржевые креды, оркестрация агентов и MCP,
сырое хранилище платформы.

## Гейты

```bash
npm run check    # ЕДИНЫЙ гейт: test → build → conformance:validation
```

`check` — ровно то и в том же порядке, что гоняет CI: и PR-гейт, и релизный workflow. Состав
живёт только в `package.json`, чтобы «зелёный локально», «зелёный на PR» и «зелёный на релизе»
не разошлись в смысле; форма обоих workflow зафиксирована тестами `test/*-workflow-guard.test.ts`.

Перед релизом дополнительно `npm run sdk:pack` и `npm run sdk:verify` — это **проверка упаковки,
а не канал доставки**.

## Правила и грабли

- **Порядок кросс-репо изменения:** сначала источник истины (`platform`), затем SDK, затем
  потребители. Обновить examples, метаданные версии и changelog до того, как потребители сочтут
  способность стабильной.
- Внутренности платформы не тянуть: SDK остаётся standalone-фасадом.
- Деньги — только `decimal.js`.
- **Канонический канал доставки — npm, и только он.** Релиз = `npm publish` через workflow
  **SDK Release** (`workflow_dispatch`), который сам гоняет `npm ci → check → sdk:pack →
  sdk:verify → npm publish --provenance` и fail-closed, если версия уже в реестре или
  `package.json` не совпал с входом. У PR-гейта нет ни `id-token`, ни secrets, ни registry-url —
  он физически не является каналом публикации. GitHub tag/release — вторичная заметка без тарбола.
- **Реестр npm иммутабелен:** ошибка правится новым patch-релизом, не переизданием.
- **Меняешь публичную поверхность — пересобери `api-surface.txt`** (`npm run api:surface`) и
  закоммить в том же PR: `check` краснеет, если коммиченный снимок не равен регенерации.
  Удаление или изменение строки снимка требует minor-бампа относительно опубликованного `latest`
  и секции этой версии в `CHANGELOG.md`; исключение — строка в `api-breaking-allowlist.json` с
  причиной, ISO-датой и PR. Добавления не требуют ничего.
- **Пока `0.x`, breaking-изменение может выйти minor-бампом** — это записано явно, а не
  подразумевается: semver не даёт гарантий ниже 1.0.0, а поверхность ещё движется. Обязательно
  с записью в `### Changed` и migration note. Потребителям это не всплывает само: caret пинит
  minor для `0.x`, так что переход — всегда осознанная правка на их стороне.
  Полное правило — control-center `docs/delivery/versioning-policy.md`, решение — ADR-0029.
